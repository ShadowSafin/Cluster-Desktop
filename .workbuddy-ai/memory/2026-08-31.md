# Cluster CLI — Phase 1 build session

## What landed

Built the multi-package TypeScript skeleton for **Cluster CLI**, a terminal-first AI coding assistant. The repo at `C:\Coding Agent` is a `cluster`-namespaced npm workspace with:

- `apps/tui` — Ink-based terminal UI, commander CLI (`start`, `resume`, `sessions`, `config`, `config-get`, `config-set`, `doctor`).
- `packages/agent-core` — planning + agent loop + OpenAI-compatible provider, native-function-calling with auto-degrade to a fenced-JSON text protocol.
- `packages/tool-runtime` — tool registry, file/command/git tools, `patchFile` based edits, danger classification in `safety.ts`. Backups before every edit.
- `packages/workspace` — project-root detection, manifest parsing, git status, chokidar watcher.
- `packages/storage` — session persistence via lowdb JSON, debounced writes, corrupt-file quarantine.
- `packages/shared` — types, ids, Pino logger, `diff`, path utilities.

## Notable fixes this turn

- `safety.classifyPath` was missing `package-lock.json` style lockfiles. Updated the regex in `packages/tool-runtime/src/safety.ts` to catch `*.lock`, `*.sum`, `*.sync`, and hyphenated forms like `package-lock.json`.
- `util.readTextFile` was hiding `EISDIR` by returning `null` when the target was a directory; that got rerouted to `ENOENT` upstream. Now it throws a real `EISDIR` error so `describeFsError` can surface the right code to the agent.

## New tests
